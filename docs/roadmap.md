## M1 可靠角色基础

目标是在隔离的模拟环境中，用一个核心角色、三个身份、两个模拟平台完成「入站 → 授权召回 → 决策与草稿 → 审批 → 模拟回执 → 审计」。外部自动发布保持关闭。

| 工作包 | 依赖 | 交付 | 验收 |
| --- | --- | --- | --- |
| **M1.1 上下文和记忆授权** | 已落地的身份绑定与 Worker | 补齐会话、联系人、记忆、来源和授权的最小关系模型。以固定 Run 绑定构建检索上下文。数据库先按归属、来源状态、用途、受众、期限和授权过滤，再返回允许排序的候选。撤权推进 `authEpoch`，并使受影响的派生内容失效。配置独立数据库运行角色和 RLS。 | 验证四层作用域、组合外键、公司机密隔离、用途分离和撤权后的拒绝。先通过 AT-02、AT-03 的检索部分。 |
| **M1.2 选择性召回与草稿** | M1.1 | 在已授权集合内做关键词召回。联系人关系信号随关系模型接入。补齐上下文快照、召回预算、受限候选与确定性排序。通过显式注册表装配两个模拟平台和假模型。分开调用内部决策与对外写作，持久化规范化草稿和证据引用。 | AT-01 至 AT-03 的草稿路径通过，注入内容不能改变账号绑定，重复事件只产生一份草稿。覆盖 AT-06、AT-08 的认知路径及 PL-01。 |
| **M1.3 管理端认证与授权** | 已落地的角色关系。可与 M1.1 至 M1.2 并行 | 接入可信身份提供方和角色授权，按资源归属校验命令与查询。建立最小 OpenAPI 契约、版本校验、命令幂等、审计与错误返回。基于此开放角色、身份、账号和授权配置入口。 | 验证未登录、越角色访问、角色权限错配及旧版本修改。Cookie 会话验证 CSRF。业务管理端点开放前通过此工作包。 |
| **M1.4 人工审批** | M1.2、M1.3 | 提案绑定账号、目标、受众、内容、证据和策略版本。提供审批待办、详情和并发安全的批准或拒绝。Vue 管理端展示身份、拟发送内容、风险码及模拟状态。 | AT-05 通过。草稿、绑定、授权或适配器版本变化时，未执行提案的旧审批失效。覆盖 PL-04 的审批部分。 |
| **M1.5 模拟执行与对账** | M1.4 | 实现发送前复核、预算预留、唯一活动尝试、模拟回执、未知结果对账和角色／身份／账号暂停。分离模拟队列、凭据和数据写入范围。 | AT-04、AT-07、AT-09、AT-10 通过。未知结果无盲目重发，模拟真实写调用为 0。补齐 AT-06 的执行路径及 PL-02、PL-04。 |
| **M1.6 调度与验收** | M1.5 | 以数据库计划和事务出箱触发运行。处理时区、静默时段、配额窗口、重启补偿与取消旧计划，用固定时间和承诺夹具覆盖边界。加上回放、结构化审计及队列、审批、对账的关键监控。 | AT-11 通过。跑通三身份、两模拟平台的完整场景，并按规范完成隔离、故障恢复与检索基准验证。 |

**M1 退出条件。** AT-01 至 AT-11 以及第 17 章要求的 M1 插件用例全部通过。跨身份泄露、审批绕过、模拟外发和已确认重复写入均为 0。按设计规范的数据规模验证授权检索与重排 P95 ≤ 300 ms，统计时间不含模型调用。真实平台试点独立验收，先用测试账号验证官方接口、披露、账号识别、回执和对账；启用真实只读连接器或常驻轮询前补验对应插件场景。
