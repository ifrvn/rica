## 插件架构重构

- P0 基线通过。独立 PostgreSQL 18 与 Redis 8 上，三身份双平台的入站到模拟回执、69 项集成测试和出箱冒烟通过，既有检索基准默认跳过。
- P1 已建立注册校验和生命周期。定向测试覆盖必需配置失败、可选依赖缺失、启动失败逆序清理及幂等停止，类型检查通过。生产进程在 P2 切换装配入口。[重构计划](plugin-architecture-refactor.md)

- P2 模拟主链已由进程入口装配。模型默认 `simulated`，模拟平台默认启用 `mock-a,mock-b`。可在 API、认知 Worker 和模拟执行器使用同一份 `RICA_SIMULATED_PLATFORMS` 配置，按逗号分隔选择 ID，显式空值停用全部模拟平台。旧入站、提案摘要、出箱事件和模拟回执继续使用原结构。停用平台的草稿跳过模型调用，审批预览隐藏正文，执行检查拒绝新许可。既有回执和在途对账继续沿用原账本。
- P2 的范围为两个模拟平台。现有管理接口及数据库仍限定模拟平台 ID，后续平台接入按 P3–P5 推进。本阶段的回退可使用上一版应用与配置，无需反向数据库迁移。 类型检查、生产构建、10 项单元测试、70 项集成测试和出箱冒烟通过，既有检索基准默认跳过。

- P3 模拟审批策略更新为版本 3。新提案将执行适配器 ID、实现版本和契约版本一起纳入审批摘要。预览、审批与许可发放共享相同的版本判定。新许可保存原审批摘要，数据库拒绝旧执行入口插入未绑定的许可。回放展示实际适配器信息，旧提案缺失字段显示为空。
- 升级前待审或已批准但尚无许可的模拟提案需重新生成和审批。已发放许可的尝试继续走原回执复核与账本，已确认回执保留。旧库验收覆盖旧待审、已批准、在途和已确认记录。 类型检查、生产构建、10 项单元测试、71 项集成测试和出箱冒烟通过，既有检索基准默认跳过。发布时按计划协调停止旧审批入口、认知 Worker 与模拟执行器，再应用迁移并启动同一版本的进程。回退时维持新许可暂停，保留迁移与在途账本。[切换与回退](plugin-architecture-refactor.md)

## M3 交付记录

1. **M3 身份状态。** 已校验的模拟入站写入身份级动机与情绪修订。v1 使用 24／8 小时半衰期，重复投递只应用一次，乱序按有效时间和事件 ID 从最近有效检查点重放。未来时间戳按接收时间截断。状态只进入当前身份的内部决策，无修订的运行使用基线。联系人边界按运行创建时固定的版本复核，旧运行沿用原时序校验。
2. **M3 规则与每日投影。** 管理员可在身份版本中配置半衰期及事件增量，重放保留每个事件使用的原配置。共享精力由管理员预先批准，按角色和 UTC 日发布一个档位，缺省为 NORMAL。
3. **M3 观点与偏好版本。** 管理 API 按身份记录证据和演化结果，同一登记来源只计一次。支持不足留作候选，强冲突追加争议版本。回滚追加新版本并复核证据，失效版本隐藏内容。入口与限制见[身份观点与偏好](management-api.md#身份观点与偏好)。
4. **M3 观点决策投影。** 模拟内部决策只读取当前身份已核验的正式观点，并标记为主观判断。写作输入使用独立授权，回放只记录观点版本引用。观点在模型运行期间被替代或在执行前失效时，拦截对应提案。
5. **M3 每日反思。** Worker 按身份整理上一 UTC 日的已确认模拟回执和未核实入站计数，单独标注虚构档案。单一有效身份记忆可生成待复核偏好，按来源去重。
6. **M3 自主目标与账号资格。** 已确认模拟互动可在身份许可内生成复盘目标，受主题、预算、期限和三个活跃目标名额约束。账号资格按绑定独立评估，模拟阶段的外部 AUTO 关闭。

| 逐账号资格 | 活跃和暂停的账号分别返回绑定状态和适配器原因。M3 验收使用模拟适配器，外部 AUTO 资格均为否。 |

## M4 交付记录

1. **M4 混合检索。** 排序 v2 在用途授权集合内融合关键词、有限的中英文同义概念和当前会话信号。概念采用本地词表，适用范围由词表决定。旧快照继续按原证据与排名回放。十万条、十并发检索基准 P95 为 269.1 ms。
2. **M4 跨平台去重。** 身份显式启用后，只比较其活跃账号在不同平台收到的已验证公开内容。命中时为审批附加风险码。私聊、未启用身份和其他身份的内容不参与比较。
3. **M4 长期评测。** 角色日报汇总 UTC 日行为、审批、重复提示、回执和预算。数据库原子预留模型额度，日报比较两段 7 日窗口并报告漂移。

检索环境为 Windows 上的 Node.js 26.12.1，Docker Linux 虚拟机报告 12 个逻辑 CPU 和约 13.6 GiB 内存，运行 PostgreSQL 18.6 和 Redis 8.10.3。夹具为同一角色的 10,000 条已批准 CORE 记忆和每个身份 30,000 条 IDENTITY 记忆，约 1% 的 ASCII 短文本匹配同一主题，每条记忆有公开来源，采用原生作用域授权。计时覆盖运行绑定加载、数据库授权候选查询和应用重排。正常完成时丢弃首批预热，再采样 10 批共 100 次，无模型调用。夹具准备和清理单独使用管理事务，运行角色的 2 秒数据库语句超时仍生效。

执行计划曾显示单次数据库候选扫描约 1.4 秒，重排尚未开始。优化后，行级安全策略先排除无可见授权的其他身份候选及无法命中关键词的 ASCII 候选，再按原用途、期限、受众和完整来源集合验证授权。非 ASCII 文本和当前会话证据继续由原排序器判断。回放只按已有快照的证据 ID 查找并重验。这里的延迟数据适用于上述 ASCII 夹具。

迁移只调整授权函数和读取策略。旧版应用可继续使用新迁移后的数据库，旧版请求缺省按未启用关键词预筛选处理。

在独立测试库设置 `DATABASE_URL` 和 `MIGRATION_DATABASE_URL`、应用迁移后，用 PowerShell 单独运行基准。超时、结果越权或 P95 超过 300 ms 时命令返回失败。

