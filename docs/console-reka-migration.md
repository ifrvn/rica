# 控制台 Naive UI → Reka UI 迁移路线图

迁移完成时，控制台和随仓库交付的插件界面使用 Reka UI 处理弹窗、菜单和选择等交互，使用 Vue、原生 HTML 和现有主题样式呈现表单、按钮、卡片及反馈。以当前已交付的页面、窄屏抽屉、主题和业务流程作为回归基线。

## 迁移基线

迁移前有 26 个文件直接导入 `naive-ui`，其中宿主 21 个、插件 5 个。主题菜单、服务弹层、窄屏导航抽屉和角色／身份弹窗外壳已使用 Reka UI。迁移前应用根部通过 `NConfigProvider`、`NGlobalStyle` 和主题覆盖提供全局样式及中文配置。Newbi 和外部模型插件各自声明了 Naive UI 依赖。

按阶段记录进度。每个工作包完成后，把状态更新为已验收，并记下提交号和验证结果。混用阶段的页面继续使用现有 CSS 变量，保留已部署浏览器的主题选项和外观偏好。业务命令沿用现有 API、校验规则和权限检查。

- R1 与 R2 通过浏览器验证了工作台、外部连接状态、操作审计、登录、角色切换、成员与本地账号管理、窄屏导航和主题持久化。

## 组件替换与包边界

| 当前用法 | 迁移方式 |
| --- | --- |
| `NButton`、`NTag`、`NAlert`、`NEmpty`、`NSpin`、`NCard`、`NSpace` | 原生语义元素配合现有 UnoCSS 和主题变量。按钮区分主操作、次操作和危险操作。重复的样式与行为才提取成组件。 |
| `NForm`、`NFormItem`、`NInput`、`NInputNumber`、`NCheckbox` | 使用有标签的原生表单控件，保留业务 schema 和服务端校验。按现有流程处理必填、输入长度、清空、错误反馈、提交中禁用和日期解释。 |
| `NSelect` | 固定选项使用原生选择框或 Reka UI Select。需要搜索的角色、身份、账号、会话和时区使用 Combobox，分别核对输入文本、选中值、空值和选项刷新行为。参阅 [Select](https://reka-ui.com/docs/components/select) 与 [Combobox](https://reka-ui.com/docs/components/combobox)。 |
| `NModal`、`NPopover` | 将业务弹窗迁移到 Reka UI Dialog，账号菜单使用与现有操作语义匹配的 Popover 或 Dropdown Menu。按场景校验初始焦点、焦点限制、关闭条件、焦点归还和移动端滚动。参阅 [Dialog](https://reka-ui.com/docs/components/dialog)。 |

宿主和插件都需要的组件通过 `@rica/console-shared` 的公开入口提供。页面专用组件随所属功能维护。迁移时清理对应的 `.n-*` 样式，并确认生产构建能扫描到共享组件和插件使用的 UnoCSS 类及 Iconify 图标。

## 回归检查

- 每个阶段运行 `pnpm run typecheck` 和 `pnpm run build`。局部迁移优先验证受影响的页面及入口，整体验收覆盖已有主链和插件流程。
- 浏览器覆盖 320px 窄屏、桌面宽屏、键盘操作、浅色和深色。重点检查弹窗内下拉、长列表滚动、层级、遮罩关闭、返回焦点，以及加载、空态、无权限、请求失败和重试。
- 关键写入使用隔离环境或协议夹具。核对提交内容、目标角色与账号、重复请求、审批人与提案人分离和版本冲突。真实平台发送按仓库测试规范验证。
- 最终运行 `pnpm install --frozen-lockfile`、`pnpm run typecheck`、`pnpm test` 和 `pnpm run build`，核对依赖清单、锁文件与构建模块。正式交付前走一轮从登录、发起模拟、审批到回执及审计的浏览器验证。
