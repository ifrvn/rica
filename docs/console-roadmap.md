# Rica 控制台功能规划

控制台面向角色管理员、审批员和审计员。首个版本让操作者在网页内完成「创建角色 → 配置身份与模拟账号 → 发起一次模拟 → 审批 → 查看回执」。登录账号仍由现有 CLI 初始化，实际执行仍由独立执行器负责。

依据[开发路线图](roadmap.md)、[管理 API](management-api.md)与[插件架构计划](plugin-architecture-refactor.md)。

## 1. 当前能力

| 已有界面 | 当前边界 |
| --- | --- |
| 服务状态 | 可查 API、PostgreSQL 和 Redis 就绪情况。角色级积压、审计与运行回放已有 API。 |
| 登录和会话 | 支持本地密码登录、Passkey 登录与登记、退出。角色成员由管理 API 配置。 |
| 角色切换 | 审批页可以选择可访问的角色。创建角色、修改核心、管理身份和账号目前走 API。 |
| 人工审批 | 模拟提案支持待办分页、正文复核、批准和拒绝。本机连接器提案需输入 ID 查询后审批。缺少统一运行入口、回执详情与异常处置页面。 |

当前主要缺口是操作流程。控制台要将已有的角色配置、执行记录和安全控制连接起来，并为缺少可发现入口的操作补齐最小查询 API。

## 2. 信息架构

| 一级入口 | 主要内容 | 首次交付 |
| --- | --- | --- |
| 工作台 | 当前角色的状态、待审批或待处理事项、最近运行。按当前用户权限提供可执行入口。 | C1 |
| 角色与身份 | 角色列表、核心配置、身份、平台账号。角色状态和暂停入口固定在角色页。 | C1 |
| 审批 | 模拟提案与本机连接器提案分栏，查看目标、正文、证据风险、决定和结果。 | C1 模拟，C2 本机连接器 |
| 运行 | 最近运行、阶段与回执，后续增加积压、隔离事件与对账。 | C1 运行与回执，C2 异常处置 |
| 插件 | 查看部署的插件、进程状态和当前角色的连接器绑定。 | C2 |
| 知识与成长 | 记忆与来源、授权、目标、反思、观点和精力。身份在模块内固定。 | C3 |
| 权限与审计 | 角色成员、权限分配、操作记录。个人会话与 Passkey 从顶部账号菜单进入。 | C2 审计，C3 成员 |

顶部保留角色选择、服务状态和个人菜单。默认落到当前用户能完成的首个任务。首次登录且没有角色时，有创建权限的用户可直接进入创建流程，其他用户看到等待授权状态。待交付的导航随功能上线。切换角色时清除上一个角色的详情、列表和待提交操作，忽略返回较晚的请求。列表入口和所选详情支持刷新及浏览器返回。链接保存角色、页面及详情 ID，草稿和审批理由留在当前操作中。后续筛选上线时再将筛选条件接入 URL。

## 3. 分阶段交付

### C1 模拟操作闭环

已接入角色与身份工作区、模拟账号登记、模拟发起、审批待办、运行分页与回执详情。控制台为每次模拟创建独立公开会话，沿用正常审批和独立执行器。隔离环境已用管理员和独立审批员在浏览器验证发起、批准和回执。角色、审批提案及运行详情支持直达链接。刷新与浏览器前进、返回会恢复角色和所选详情。隔离浏览器夹具已验证登录后恢复、越权拦截，以及切换角色后忽略迟到响应。

- 控制台骨架与权限导航。会话读取返回当前主体是否可创建角色，角色上下文返回自己的权限集合。角色列表沿用服务端分页。
- 角色与身份配置。创建和编辑核心、创建身份、绑定模拟账号，显示暂停原因和当前配置版本。启用、暂停和恢复沿用现有控制命令。
- 「运行一次模拟」引导。管理员选择包含身份的模拟账号，输入模拟消息后启动运行。宿主为每次运行建立独立公开模拟会话，写入事件和事务出箱，随后交给正常 Worker、审批与执行链路。模拟始终限定在模拟账号和模拟适配器。
- 复用现有审批交互，补最近运行列表和回执详情。审批决定与执行结果分别展示。管理员和审计员按权限查看回放；审批员仅查看其审批页有权读取的内容和结果摘要。

**验收** 从独立空库完成账号初始化后，ADMIN 能在网页创建角色、身份和模拟账号，启动一次模拟并获得可点击的运行记录。独立 REVIEWER 能看到待办并批准。执行器生成唯一模拟回执，ADMIN 可从运行列表进入回放。双身份验收确认账号和审批内容始终对应所选角色与身份。全过程无需手填资源 UUID。

### C2 日常运行与异常处置

首批已接入角色积压与隔离出箱。ADMIN 可按事件代次填写理由恢复，AUDITOR 可查看事件和关联运行。隔离浏览器已验证版本冲突后的重新核对、理由保留和恢复后计数更新。

- 工作台补角色级积压与明确的处理入口。运行列表支持状态、身份、账号和时间筛选，详情串联入站、草稿、审批、许可及回执，正文按现有授权投影展示。
- 将隔离 Outbox、模拟对账、审计和本机连接器事件接到控制台。补本机连接器提案的角色级分页与状态筛选，以审批队列替代手填 ID。
- 上线「插件」页，提供脱敏状态和当前角色的连接器绑定。配置与执行权限按插件专项规划分期。
- 暂停、撤销、恢复和对账各自显示作用域与后果。未知结果只提供对应的对账或结案入口。隔离事件恢复使用当前代次和理由。

**验收** 从积压进入对应记录，ADMIN 可在权限范围内完成一次隔离恢复和一次对账，AUDITOR 可查看关联记录，越权用户直接访问详情仍被 API 拒绝。管理员可在网页找到本机连接器的待审提案和结果状态。隔离夹具验证重复提交、暂停和未知结果处理。

### C3 配置、知识与审计

- 角色成员列表和授权编辑，明确 ADMIN、REVIEWER、AUDITOR、OPERATOR 在当前角色的有效权限。创建本地账号继续走 CLI。保留至少一名 ADMIN 的限制。
- 记忆按身份、作用域和状态浏览元数据，关联来源、修订和授权。授权表单按用途限定可选的账号、会话与联系人，并展示期限。纠错、撤销和观点恢复沿用版本检查与审计。
- 身份详情增加目标、反思、观点、精力和关系边界。先接现有可查询详情；需要浏览的观点和联系人补作用域内分页。计划和承诺放在角色的运行配置区。
- 工作台增加近期预算、漂移与评测摘要。指标保留角色、时间范围和模拟标识。

**验收** ADMIN 在网页配置成员与限定用途的记忆授权，AUDITOR 按既有权限追踪来源和操作。跨角色授权、私聊绑定错配、撤销后继续使用和移除最后一名 ADMIN 均由服务端拒绝。错误后保留用户已填输入，便于重新确认提交。

### 后续候选

管理员账号生命周期、自定义角色权限和批量操作各自立项。插件配置、启停和安装流程见下一节。

## 4. 插件专项

当前插件随 Rica 部署，由进程启动时的允许列表装配。宿主已能输出就绪和失败诊断，控制台需要补查询 API。列表按能力区分模型、模拟适配器、只读连接器和发送执行器。角色内的账号绑定与部署级插件生命周期分别管理。[插件架构计划](plugin-architecture-refactor.md)

| 阶段 | 控制台功能 | 操作边界 |
| --- | --- | --- |
| C1 配置入口 | 创建模拟账号时只提供当前部署启用的模拟适配器。若对应能力不可用，说明原因并保留用户填写的配置。 | 优先复用 API 进程已装配的允许列表。模拟触发仍只接受模拟账号。 |
| C2 插件页 | 查看插件 ID、实现版本、契约版本、能力、所属进程及最近脱敏诊断。进入详情查看当前角色的账号绑定，复用平台账号的暂停与恢复规则。 | 状态来自对应进程的报告，API 进程自身就绪不代表 Worker 就绪。缺少报告显示「未知」，单次连接器退出后显示最近结果。角色 ADMIN 只能管理本角色的绑定。 |
| C2 连接器配置 | 从插件详情跳到平台账号，选择身份并登记账号绑定。按平台能力查看读取状态、最近成功时间和错误码，进入提案与回执。 | 凭据沿用部署注入。配置响应、日志和审计均不返回凭据。身份核验或授权失败时保留暂停状态。读取与发送分别显示可用性，核验读取权限不授予发送权限。 |
| 后续独立交付 | 部署管理员管理受信插件的安装、启用、停用、升级与卸载。显示版本变更、影响的进程和账号、配置验证结果及变更记录。 | 增加部署级权限，独立于角色 ADMIN。先支持受信发布源和固定版本，由部署流程更新并重启对应进程。任意 npm 包安装、代码上传和热加载由后续隔离方案评估。 |

部署变更流程为「选择受信插件与固定版本 → 校验契约、依赖及配置 → 预览受影响进程和账号 → 确认变更 → 观察启动结果」。配置先区分插件实例参数、账号绑定和凭据引用。凭据托管与轮换有独立验收后再开放写入。模型提供方选择先保留在部署配置，出现角色级配置需求再确定授权和预算边界。

停用或卸载前列出绑定及待核对的执行尝试。暂停受影响的账号，阻断新发送许可，保留审计、回执和待核对记录。未知结果只走原实现与原幂等键的受控恢复，原实现不可用时由管理员人工处置。

**C2 验收** 模拟 Worker、只读连接器和发送执行器分别显示状态，停止 Worker 后失效报告不会一直显示就绪。跨角色绑定不可见，角色 ADMIN 不能更改部署配置。暂停账号后不能领取新发送许可。验证期间使用隔离夹具，控制台查询和状态核验产生的真实写请求为零。

## 5. API 缺口与实施顺序

| 阶段 | 优先复用 | 需要补齐的服务端能力 |
| --- | --- | --- |
| C1 | 本地会话、角色／身份／账号配置、控制命令、模拟审批、运行回放 | 会话的创建角色能力、当前角色自身权限投影、已启用模拟适配器选项、受控模拟触发与独立会话创建、角色级运行分页、按审批权限裁剪的结果投影。 |
| C2 | 角色级监控、Outbox 隔离与恢复、模拟对账、审计、本机连接器事件与单提案查询 | 本机连接器提案分页、运行与审计记录的最小关联索引、按进程的脱敏插件状态和按角色的绑定投影。 |
| C3 | 成员授权写入、记忆元数据与来源、授权、目标、反思、观点详情、计划、承诺、评测 | 成员列表、观点与联系人分页，以及授权表单所需的角色内受控选择项。 |

C1 按以下顺序实现并验收。

1. 拆分会话、角色上下文和审批组件，建立可直达的路由及统一请求层。
2. 交付角色、核心、身份和模拟账号表单，补齐创建角色权限与角色权限投影。
3. 接入模拟触发、运行分页及结果投影，贯通双用户审批到回执。
4. 用临时 PostgreSQL 和 Redis 完成一轮浏览器验收，再进入 C2。

所有新增查询在服务端按角色校验，分页与筛选由服务端处理。配置写入沿用版本头、幂等键和审计。遇到版本冲突时提示重新核对并保留用户输入。保留 API 对跨角色资源和权限不足的区分。控制台按权限展示按钮，API 负责最终授权。插件状态接口只返回声明元数据和脱敏诊断。

## 6. 交互与测试约定

- 继续使用 Vue 3、Naive UI 和 pnpm。用布局、表格列和状态标识表达层级，每页突出一个主操作。列表使用名称，详情提供复制 ID。明确区分模拟、待执行、已确认与结果未知。
- 校验状态要覆盖加载、空数据、无权限、会话过期、版本冲突和失败重试。主要流程可键盘完成，窄屏保留目标、内容和审批操作。
- C1 重点覆盖角色切换时的异步数据隔离、最小权限导航、重复模拟触发和审批幂等。C2 重点覆盖越权查询、未知结果与重复恢复。C3 重点覆盖来源授权和成员权限边界。
- 每阶段更新[路线图](roadmap.md)，记录已上线页面、开放的权限、完成的验收与下一阶段范围。
