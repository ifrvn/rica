# 模拟执行进程

批准后的模拟提案进入 `READY`。独立执行进程从 PostgreSQL 读取这些提案，认知 Worker 继续使用原有 BullMQ 队列。执行进程使用自己的数据库凭据，只调用本地模拟回执函数。

## 启动

1. 使用迁移账号执行 `pnpm run db:migrate`。
2. 创建独立数据库登录并授予 `rica_simulation_executor`。将该登录的连接配置到 `RICA_SIMULATION_EXECUTION_DATABASE_URL`。
3. 在项目目录运行 `pnpm run dev:simulation`。

```sql
GRANT rica_simulation_executor TO rica_simulation_login WITH INHERIT TRUE, SET TRUE;
```

示例中的登录名称按部署替换。此进程只处理 SIMULATION，数据库角色不能读取草稿正文、记忆或入站载荷，也没有平台客户端及写凭据。

## 许可与恢复

- 许可前复核批准摘要、有效期、账号与会话绑定、证据授权、批准正文中的 AI 披露、策略与适配器版本。披露在送审前从固定核心版本附到正文并纳入摘要。每日按角色当地时间重置每账号五次额度。已绑定联系人按账号在滚动一小时内最多确认一次回复，换会话仍计入同一窗口。当地 22:00 至次日 08:00 延后处理。每个账号同一时刻最多有一份进行中或结果未知的尝试。
- 有效许可和预算预留一起写入数据库。模拟回执以提案 ID 唯一落盘。收到回执后运行进入 `SIMULATED`。已确认未发生的写入释放预算并进入 `BLOCKED`。
- 进程中断时，对账仅查已有回执。许可过期且没有回执时进入 `RECONCILING`，保留预算和账号占用。后台不会对未知结果自动重发。
- 暂停与许可使用同一角色锁。已批准但未取得许可的提案随撤权失效。已取得许可的尝试在本地写入前还会复核绑定、正文摘要、有效期和记忆证据授权，已写入的回执可以在暂停期间继续对账。

## 人工对账

在控制台的「运行」中打开状态为「待对账」的模拟运行。管理员点击「核对账本」，确认封存证据后填写对账理由并提交。版本发生变化时，重新核对后可使用原理由提交。

未知尝试在许可过期 15 分钟后可由当前角色的 ADMIN 处置。先读取 `GET /v1/characters/{characterId}/actions/{actionId}/reconciliation`，取得版本、账本支持的结论和证据引用。尚未到人工处置时间时，结论和证据引用为空。

向同一路径发送 POST，带 `Idempotency-Key`、GET 返回的 `If-Match` 版本，以及 `outcome`、`evidenceRef`、`reason`。服务会在角色锁内重查本地账本。已有回执支持 `CONFIRMED`，封存许可没有回执时支持 `DEFINITELY_NOT_SENT`。确认未写入会释放账号和预算，原提案进入 `BLOCKED`。系统不会重发原提案。操作人、理由和证据引用随结果保存，管理审计记录同事务追加。

旧策略下待审或已批准的草稿需要重新生成和审批。已产生的历史回执和预算记录保留，已绑定的联系人会回填到历史尝试。
