# 模拟运行、调度与对账

批准后的模拟提案进入 `READY`。独立执行进程从 PostgreSQL 读取这些提案，认知 Worker 继续使用原有 BullMQ 队列。执行进程复用 `DATABASE_URL`，连接时切换到 `rica_simulation_executor`。

## 启动

1. 使用迁移账号执行 `pnpm run db:migrate`。
2. 在项目目录运行 `pnpm dev` 启动整套应用，或运行 `pnpm dev simulation` 单独启动模拟执行器。

此进程只处理 SIMULATION。执行角色不能读取草稿正文、记忆或入站载荷。执行进程没有平台客户端及写凭据。

模拟群聊的一份回复草稿可包含 1 至 3 条消息。审批按发送顺序展示整组内容，批准一次后由执行器整体写入本地账本，计为一次执行。会话逐条展示消息，后续模型也按相同顺序读取。消息内的换行保留在原消息中。

## 模拟设置

角色管理员可在「模拟运行 → 模拟设置」调整限制。保存后，等待中的执行和定时任务会按新设置评估。已生成提案沿用生成时的有效期。

| 设置 | 默认值与适用范围 |
| --- | --- |
| 每账号每日执行次数 | 5 次，按角色当地午夜重置。填 0 表示不限。 |
| 联系人回复间隔 | 60 分钟，同一账号跨会话计算。填 0 表示不限。 |
| 静默时段 | 角色当地 22:00–次日 08:00，适用于常规模拟与定时触发。可以关闭，或选择一并限制手动模拟群聊的回执。 |
| 每日定时任务补跑窗口 | 120 分钟。超出窗口时跳过错过的这一轮。 |
| 提案有效期 | 新提案从生成起 24 小时。 |
| 每日模型预算 | 默认沿用角色核心预算，角色未设置时为 10,000,000 估算单位。按 UTC 日累计，可单独覆盖模拟使用的上限。 |

## 许可与恢复

- 许可前复核批准摘要、有效期、账号与会话绑定、证据授权、策略与适配器版本。角色核心设定与身份提示词作为写作模型的系统提示。审批摘要绑定最终回复正文和本次运行使用的配置版本。每个账号同一时刻最多有一份进行中或结果未知的尝试。
- 有效许可和预算预留一起写入数据库。模拟回执以提案 ID 唯一落盘。收到回执后运行进入 `SIMULATED`。已确认未发生的写入释放预算并进入 `BLOCKED`。
- 进程中断时，对账仅查已有回执。许可过期且没有回执时进入 `RECONCILING`，保留预算和账号占用。后台不会对未知结果自动重发。
- 暂停与许可使用同一角色锁。已批准但未取得许可的提案随撤权失效。已取得许可的尝试在本地写入前还会复核绑定、正文摘要、有效期和记忆证据授权，已写入的回执可以在暂停期间继续对账。

## 人工对账

在控制台的「运行」中打开状态为「待对账」的模拟运行。管理员点击「核对账本」，确认封存证据后填写对账理由并提交。版本发生变化时，重新核对后可使用原理由提交。

未知尝试在许可过期 15 分钟后可由当前角色的 ADMIN 处置。先读取 `GET /v1/characters/{characterId}/actions/{actionId}/reconciliation`，取得版本、账本支持的结论和证据引用。尚未到人工处置时间时，结论和证据引用为空。

向同一路径发送 POST，带 `Idempotency-Key`、GET 返回的 `If-Match` 版本，以及 `outcome`、`evidenceRef`、`reason`。服务会在角色锁内重查本地账本。已有回执支持 `CONFIRMED`，封存许可没有回执时支持 `DEFINITELY_NOT_SENT`。确认未写入会释放账号和预算，原提案进入 `BLOCKED`。系统不会重发原提案。操作人、理由和证据引用随结果保存，管理审计记录同事务追加。

## 群聊词库

公开模拟群聊使用托管模型时可学习群内黑话。词条至少需要两位群员的三条不同用例，重复文本按一次计。词库仅在原群聊内生效，每次调用最多加载四条与当轮相关的词。释义作为结构化参考数据传给模型。写作仅在发言者已使用该词、语气适配时可以复用中性和玩笑用法。

群聊详情附词条、来源及纠正和停用入口。运行详情展示当轮实际引用的版本。来源不可用时停止召回和展示派生释义，引用旧版本的待审草稿不能继续执行。

## 群聊回复时机

同一群员五分钟内重复发送同一条消息时，已有回复或有效提案的消息会跳过。闲聊接话在消息发出十分钟后失效。若群内已有至少两名群员发布四条不同的新消息，闲聊接话也会提前关闭。直接提问和相关话题的回复沿用角色设置里的提案有效期。

失去时机的提案从待审批列表移除，并在运行详情显示原因。审批和执行前会复核。已批准的模拟回复若错过时机，执行器会拦截并保留审批记录。

仍需人工处理的提案会显示转人工类别和具体理由，区分策略要求、上下文不足、审核模型未能完成以及模型判断需复审。

## 计划调度

启动认知 Worker 后，它会从 PostgreSQL 扫描到期的模拟计划。计划推进、触发记录、运行、审计与 `RunQueued.v1` 出箱事件在同一事务提交。BullMQ 消费沿用已有流程。

### 创建和更新

角色的 ADMIN 可调用 `GET /v1/characters/{characterId}/schedules` 查询计划，或向同一路径提交 POST 创建计划。POST 带 `Idempotency-Key`。请求包含 `scheduleKey`、`accountId`、`conversationId`、`zone`、`enabled` 和 `rule`。私聊还须提供已绑定的 `contactId`。

- 每日活动使用 `{"kind":"DAILY","localTime":"09:30"}`，按计划的 IANA 时区解释。
- 单次提醒使用 `{"kind":"REMINDER","dueAt":"2026-11-10T01:30:00.000Z"}`，按指定的 UTC 时刻触发。

对 `/schedules/{scheduleId}` 执行 PUT 时发送 `If-Match`，例如 `"1"`，并提交新的 `zone`、`enabled` 和 `rule`。账号和会话固定。更新计划会取消旧版本中尚未执行的运行。一次计划的同一计划时刻只产生一条触发记录。

### 调度边界

- 夏令时跳过不存在的本地时刻，重复时刻采用较早的 UTC 瞬间。
- 停机恢复时，每日计划只补最近一个合规时刻，补偿窗口为两小时。角色当地时间 22:00 至次日 08:00 跳过每日活动。
- 单次提醒在静默时段延期到下一次 08:00，保留原计划时刻。账号暂停期间保留待处理计划，恢复后重新计算。
- 定时触发准备模拟认知上下文。承诺提醒保留承诺与触发记录的关联。

模拟入站事件键的 schedule: 前缀保留给调度器。外部模拟事件使用该前缀时会被拒绝。

### 承诺提醒

角色的 ADMIN 可用 `GET /v1/characters/{characterId}/commitment-receipts` 查找尚未登记的已确认回执，也可按 `runId` 筛选。用 `POST /v1/characters/{characterId}/commitments` 登记时，提交 `actionId`、`title`、`task`、UTC 格式的 `dueAt`、`reason` 和 `collaborators`，并带 `Idempotency-Key`。无协作时提交空数组。协作身份须有当前角色的有效账号绑定。每张确认回执最多登记一条承诺，回执对应的负责身份、账号、会话和联系人用于唯一一条单次提醒。

通过 `GET /v1/characters/{characterId}/commitments` 查询，可按 `accountId` 或 `contactId` 过滤。响应包含承诺状态、版本和关联提醒的下次触发时间。

普通模拟回复的生成、审批和回执均不能登记计划或承诺。计划由管理命令创建。承诺可由管理员从已确认的回执登记，并保留原会话和回执。登记后的提醒沿用模拟调度和静默时间规则，真实平台的参与事项由人工跟进。

对 `/commitments/{commitmentId}` 执行 PUT 时提供 `If-Match` 和变更理由。操作为 `EDIT`、`DEFER`、`FULFILL`、`CANCEL` 或 `EXPIRE`。编辑可修改标题、事项、截止时间和协作身份。变更截止时间需要更晚的未来 `dueAt`，标记过期需已到截止时间。延期或关闭会更新提醒版本，取消旧版本尚未执行的运行。每次变更追加状态、期限、操作人和理由。

承诺提醒采用上述静默时段和补偿规则，推进到模拟上下文就绪。
